Create app/container.py with the following exact content:

```python
from __future__ import annotations

from dataclasses import dataclass
from typing import Any

_KEY_MAP: dict[str, str] = {
    "telegram": "telegram_notifier",
}


@dataclass
class ServiceContainer:
    llm_client: Any
    llm_call: Any
    verdict_parser: Any
    telegram_notifier: Any
    sentinel: Any
    briefing: Any
    coordinator: Any

    def __getitem__(self, key: str) -> Any:
        """Backwards-compatibility shim for string-key access during migration."""
        mapped = _KEY_MAP.get(key, key)
        return getattr(self, mapped)

    def __setitem__(self, key: str, value: Any) -> None:
        """Backwards-compatibility shim for test injection during migration."""
        mapped = _KEY_MAP.get(key, key)
        setattr(self, mapped, value)
```

Key design decisions (per D-04 through D-07 in CONTEXT.md):
- `llm_call` attribute holds the LLMCallService instance (added after plan 01 introduces it). If plan 01 runs first, it will be present in the dict already. If plans run in parallel, add the attribute here regardless — it will be populated in __init__.py.
- `telegram_notifier` is the attribute name (not "telegram") per D-04. The `_KEY_MAP` bridges the rename so `container["telegram"]` continues to work.
- `__setitem__` is REQUIRED — tests do `app.extensions["services"]["llm_client"] = _LLMOk()` which requires setitem support.
- Do NOT use `frozen=True` on this dataclass — it must be mutable for test injection.
- `cli_runner` is intentionally NOT an attribute (it is a local variable in create_app, not accessed by any route or test).
