```python
from __future__ import annotations

import json


class _LLMStub:
    """Deterministic LLM that returns a critical classification."""

    def chat_completion(self, **kwargs):
        return {
            "choices": [
                {
                    "message": {
                        "content": json.dumps(
                            {
                                "classification": "critical",
                                "summary": "disk full",
                                "root_cause_hypothesis": "out of space",
                                "fix_suggestion": "df -h",
                                "confidence": 0.9,
                            }
                        )
                    }
                }
            ]
        }

    def complete(self, **kwargs):
        return self.chat_completion(**kwargs)


class _FakeAlertStrategy:
    def __init__(self):
        self.calls: list[str] = []

    def send(self, message, config):
        self.calls.append(message)
        return True, None


def test_full_sentinel_pipeline_persists_event_and_exposes_via_api(client, container):
    """Prefilter → dedup → rate-limit → LLM → alert → repo → DB → HTTP."""
    fake = _FakeAlertStrategy()
    container.sentinel.llm_call_service._client = _LLMStub()
    container.sentinel.alert_service.strategy = fake
    container.sentinel.set_enabled(True)

    event = container.sentinel.process_chunk(
        container_id="abc123",
        container_name="postgres",
        chunk_text="ERROR: disk full at /data (fatal)",
    )

    assert event.status == "analyzed"
    assert event.classification == "critical"
    assert event.alert_sent is True
    assert len(fake.calls) == 1

    resp = client.get("/api/insights?limit=10")
    assert resp.status_code == 200
    body = resp.get_json()
    assert body["items"], "persisted event should surface via /api/insights"
    first = body["items"][0]
    assert first["classification"] == "critical"
    assert first["alert_sent"] is True
    assert first["container_name"] == "postgres"
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test process stdout/stderr → CI logs | Secrets or user data in test fixtures could leak into public CI logs if a test fails with a verbose assertion message. |
| Coverage HTML report → developer disk | htmlcov/ contains source snippets that could be uploaded as a build artifact; no secrets should appear in source, but test fixtures that bake in API keys would. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Information Disclosure | tests/conftest.py env vars leaking through failure messages | mitigate | Use `"test-secret-key"` literal (hard-coded, non-secret) for `SECRET_KEY` — never read from the developer's real environment. `DATABASE_URL` uses `tmp_path` so no production DB path appears in logs. Do not log `os.environ` in any test helper. |
| T-05-02-02 | Information Disclosure | LLM stub response body containing a fake API key or placeholder that looks real | mitigate | `_LLMStub` returns only the JSON verdict structure; no `Authorization` header, no `api_key`, no credential-shaped strings. Reviewed by hand — content is purely classification metadata. |
| T-05-02-03 | Denial of Service | Integration test hanging indefinitely because the coordinator thread wasn't stopped | mitigate | `START_COORDINATOR=false` in fixture env prevents APScheduler from starting; no background thread to leak across tests. `tmp_path` ensures per-test DB isolation. |
| T-05-02-04 | Tampering | .coveragerc omit list growing without review — coverage gate becomes meaningless if we omit anything the gate should actually measure | mitigate | Omit list is fixed (5 entries) and documented in the plan. Any expansion requires a new plan or an explicit retro note; code review must flag .coveragerc diffs. |
| T-05-02-05 | Repudiation | Coverage results not traceable per commit | accept | Local `pytest.ini` configuration enforces the gate at `pytest` invocation; anyone running the command sees the result. If a CI pipeline is added later (Open Question #4 in 05-RESEARCH.md), hook the same `pytest` command — no extra gate needed. |
