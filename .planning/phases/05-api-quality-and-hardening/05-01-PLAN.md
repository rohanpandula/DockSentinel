```python
def get_filtered(
    self,
    container: str | None = None,
    classification: str | None = None,
    start: datetime | None = None,
    end: datetime | None = None,
    limit: int = 100,
    offset: int = 0,
    sort: str = "-created_at",
) -> list[AnalysisEvent]:
    query = AnalysisEvent.query
    if container:
        query = query.filter(AnalysisEvent.container_name == container)
    if classification:
        query = query.filter(AnalysisEvent.classification == classification)
    if start:
        query = query.filter(AnalysisEvent.created_at >= start)
    if end:
        query = query.filter(AnalysisEvent.created_at <= end)
    order_col = (
        AnalysisEvent.created_at.desc()
        if sort.startswith("-")
        else AnalysisEvent.created_at.asc()
    )
    return query.order_by(order_col).limit(limit).offset(offset).all()
```
Note: default `limit` moves 200 → 100 to align with the route's existing override `request.args.get("limit", 100)` — this does not change observed behavior because the caller always overrides.

```python
from __future__ import annotations

from flask import Flask, jsonify
from flask_pydantic.exceptions import ValidationError


def register_error_handlers(app: Flask) -> None:
    @app.errorhandler(ValidationError)
    def _handle_validation(err: ValidationError):
        # Remap Flask-Pydantic's {"validation_error": ...} to the codebase's
        # {"error": ...} envelope (Pattern S-4). Surface the first error message
        # but do NOT echo user-supplied values — `err` stringification is
        # schema-derived and safe; raw payload fields are omitted.
        parts: list[str] = []
        for attr in ("body_params", "form_params", "query_params", "path_params"):
            raw = getattr(err, attr, None) or []
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → Flask route | Untrusted query strings and JSON bodies enter the process here. Historically parsed by hand-rolled `request.args.get` + `request.get_json(silent=True)` with ad-hoc strip/int-coercion checks. Phase 5 moves the boundary to Pydantic validation. |
| Flask route → SQLAlchemy query | Filter values (container, classification, sort direction) are passed as kwargs to repository methods; misused `sort` could become a column-name injection vector if we accepted arbitrary strings. |
| Flask error handler → HTTP response body | Error messages crossing this boundary must not echo user input (PII leak risk) and must not leak stack traces. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Tampering | `GET /api/insights` `limit` query param | mitigate | `PaginationQuery.limit: int = Field(default=100, ge=1, le=500)` — rejects negatives, non-ints, values >500 before the query runs. Prevents DOS via `?limit=1000000`. |
| T-05-01-02 | Tampering | `GET /api/insights` `offset` query param | mitigate | `PaginationQuery.offset: int = Field(default=0, ge=0)` — rejects negatives (SQLAlchemy silently ignores negative offsets but emits an invalid SQL predicate in some backends; fail-closed via Pydantic). |
| T-05-01-03 | Tampering | `GET /api/insights` `sort` query param (SQL column injection if dynamic) | mitigate | `sort: Literal["created_at", "-created_at"]` — only two literal values pass validation; no column name reaches SQLAlchemy as a string. Repo branches on `sort.startswith("-")` and uses the hardcoded `AnalysisEvent.created_at` attribute — zero dynamic-column risk. |
| T-05-01-04 | Information Disclosure | Flask-Pydantic default error envelope leaking raw user input into response bodies and Flask request logs | mitigate | `register_error_handlers` in `app/errors.py` emits ONLY the schema-derived `msg` field (e.g., "Input should be greater than or equal to 0"); never echoes the rejected value. | T-05-01-05 | Tampering | `PUT /api/settings` mass-assignment (extra keys overwriting sensitive columns like `llm_api_key`) | mitigate | Dual guard — `UpdateSettingsBody` uses `model_config = ConfigDict(extra="forbid")` (returns 400 on unknown keys), AND the existing `_ALLOWED_FIELDS` allowlist in `app/api/settings.py` is preserved as defense-in-depth. |
